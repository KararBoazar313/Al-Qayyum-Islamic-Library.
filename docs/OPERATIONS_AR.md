# دليل التشغيل والنسخ الاحتياطي — مكتبة القيّوم

## تطبيق قاعدة البيانات
من مجلد `server` وبعد ضبط `.env`:

```bash
npm install
npm run preflight
npm run migrate
npm test
```

مشغل migrations يقرأ ملفات SQL المرقمة من `database/` تصاعدياً، ويسجل ما طُبق في `qayyum.schema_migrations`. كل ترحيل يعمل ضمن معاملة مستقلة، ويُتخطى الترحيل المسجل سابقاً. خذ نسخة احتياطية قبل أي ترقية رئيسية.

## النسخ الاحتياطي والاستعادة
تحتاج أدوات PostgreSQL `pg_dump` و`pg_restore`:

```bash
DATABASE_URL='postgresql://...' BACKUP_DIR=/secure/backups ../ops/backup-postgres.sh
DATABASE_URL='postgresql://...' ../ops/restore-postgres.sh /secure/backups/qayyum-YYYYMMDDTHHMMSSZ.dump
```

ملفات النسخ تحوي بيانات شخصية وملاحظات وبيانات إدارية؛ احفظها مشفرة، بصلاحيات مقيدة، وخارج مستودع GitHub. لا تعتبر النسخة ناجحة قبل اختبار استعادتها على قاعدة منفصلة.

## متطلبات قبل فتح الخدمة
- HTTPS فعلي، و`PUBLIC_BASE_URL` و`CORS_ORIGIN` محددان بدقة.
- `JWT_SECRET` عشوائي بطول 32 محرفاً على الأقل، ولا يوضع في Git.
- PostgreSQL بعيد يستخدم TLS (`PGSSL=true`).
- `PRIVATE_STORAGE_DIR` خارج مجلد الواجهة العامة وبصلاحيات مقيدة.
- ماسح برمجيات خبيثة خارجي؛ الملفات تبقى محجورة حتى نتيجة فحص نظيفة ومراجعة حقوق مستقلة.
- حساب مالك ينشأ على الخادم فقط، مع عدم مشاركة كلمة مروره أو حفظها في ملفات المشروع.
- اختبار الاستعادة، وسجلات التدقيق، وحدود الرفع، وسياسة الخصوصية قبل استقبال الجمهور.

`npm run preflight` يفحص الإعدادات الأساسية فقط، ولا يثبت أن قاعدة البيانات أو البريد أو HTTPS تعمل فعلياً. لم تُشغّل هذه الإجراءات على خادم إنتاج ضمن هذه الحزمة.
