# حزمة استكمال المراحل 51–60 — مكتبة القيّوم

## ما أُنجز في هذه الحزمة البرمجية

### أ) موسوعة الحديث
- واجهة بحث تتصل بـ API وتتطلب تسجيل الدخول.
- البحث في متن الرواية وموضوعاتها، واسم الراوي، واسم الكتاب.
- صفحة تفاصيل للرواية تعرض اختلاف الألفاظ، والإحالات، والأسانيد، وأحكام العلماء.
- نقاط إدخال إدارية للروايات وألفاظها وطرقها وأحكامها.
- التحقق من أن الطبعة المرتبطة معتمدة في فهرس المكتبة.
- لا يصدر النظام حكماً آلياً على صحة الرواية أو ضعفها.

### ب) علم الرجال
- واجهة بحث في أسماء الرواة والأسماء البديلة.
- صفحة ترجمة تعرض حالة التحقق والسيرة وأقوال العلماء ومواضع الراوي في الأسانيد.
- نقاط إدخال إدارية للرواة والتقييمات الرجالية مع إبقاء كل قول منسوباً إلى قائله.

### ج) المخطوطات
- migration رقم 012 لإنشاء سجل وصف المخطوطات والخزائن وأرقام الحفظ وبيانات النسخ والحقوق.
- واجهة بحث في السجلات المعتمدة.
- واجهة تقديم سجل جديد للمراجعة للحسابات الإدارية.
- مراجعة المالك للسجلات المعلقة مع تسجيل القرار في سجل التدقيق.
- لا يتيح وصف المخطوط حق تنزيل صورته؛ حقوق كل نسخة رقمية تحتاج مراجعة مستقلة.

## اختبارات هذه النسخة
- Node.js: 41 اختباراً.
- Python: 9 اختبارات.
- فحص صياغة JavaScript: `node --check app.js` و`node --check server/src/index.js`.
- فحص ZIP بعد الإنشاء.

هذه اختبارات وحدات وفحوص ساكنة، وليست اختبار تكامل مع PostgreSQL أو اختبار متصفح كامل.

## ما لا يزال خارج الإنجاز المحلي
1. إدخال corpus حقيقي من الروايات والرواة والأسانيد مع توثيق كل سجل.
2. إدخال بيانات المخطوطات من فهارس المؤسسات، ومراجعة مصدر كل وصف وحقوق الصور.
3. تطبيق migrations 001–012 على قاعدة PostgreSQL فعلية.
4. تشغيل API على استضافة حقيقية وربط الواجهة بعنوانه.
5. اختبار شامل على متصفحات وأجهزة فعلية وفحص أمني مستقل.
6. إعداد النطاق وHTTPS والنسخ الاحتياطي والمراقبة، ثم النشر.

## ضوابط علمية
- لا تُدمج الطرق المختلفة تلقائياً.
- لا تُستنتج هوية راوٍ عند الاشتباه أو الاشتراك في الاسم.
- لا يُعرض حكم رجالي أو حديثي دون اسم قائله ومصدره وموضعه متى توفر.
- حالات التحقق في النظام بيانات تحريرية وليست حكماً شرعياً أو علمياً آلياً.
- لا تُنشر ملفات مخطوطات أو كتب قبل مراجعة الحقوق.
