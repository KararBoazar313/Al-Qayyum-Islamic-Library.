# إدارة الأعضاء والأقسام — مكتبة القيّوم

## الوظائف المضافة
- عرض الأعضاء والبحث بالاسم أو اسم المستخدم أو الرقم العام.
- تغيير حالة الحساب إلى نشط أو موقوف أو محظور أو بانتظار الحذف.
- إسناد أدوار المنصة الموجودة في جدول `roles` إلى حساب عضو نشط.
- إنشاء الأقسام الإدارية وتغيير حالتها.
- إسناد عضو نشط إلى قسم بصفة مدير قسم أو نائب أو موظف أو مراجع، وسحب الإسناد عبر API.
- تسجيل إجراءات الإدارة في `qayyum.audit_logs`.

## حدود الصلاحيات
- جميع نقاط إدارة الأعضاء والأدوار والأقسام محمية بشرط `account_type = owner`.
- لا يمكن تحويل حساب عضو إلى مالك أو مدير من خلال واجهة الأدوار.
- لا يمكن إيقاف حساب المالك الحالي من نقطة تغيير الحالة.
- الأدوار التنظيمية لا تمنح بذاتها صلاحية دخول لوحة المالك؛ نوع الحساب محمي بصورة مستقلة.
- يجب أن يكون العضو نشطاً والقسم فعالاً عند إنشاء إسناد جديد.

## نقاط API
- `GET /api/admin/members`
- `PATCH /api/admin/members/:id/status`
- `GET /api/admin/roles`
- `PUT /api/admin/members/:id/roles`
- `GET /api/admin/departments`
- `POST /api/admin/departments`
- `PATCH /api/admin/departments/:id/status`
- `POST /api/admin/departments/:id/assignments`
- `DELETE /api/admin/departments/:id/assignments/:userId/:role`

تحتاج هذه الوظائف إلى تشغيل migrations السابقة وقاعدة PostgreSQL وخادم API فعلي. واجهة GitHub Pages وحدها لا تشغّل قاعدة البيانات أو الخادم.
